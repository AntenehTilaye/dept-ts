 ## 0. Conventions (expand literally when typing)

- Multi-file schema in `prisma/schema/`: `schema.prisma`, `enums.prisma`, `auth.prisma` (generated), `identity.prisma`, `people.prisma`, `academic.prisma`, `workflow.prisma`, `feature.prisma`, `workitem.prisma`, `forms.prisma`, `campaign.prisma`, `scheduler.prisma`, `notification.prisma`, `template.prisma`, `document.prisma`, `thread.prisma`, `audit.prisma`, `import.prisma`, `availability.prisma`, `reporting.prisma`, `search.prisma`, `dashboard.prisma`, `committee.prisma`, `portfolio.prisma`, `meeting.prisma`, `planning.prisma`, `load.prisma`, `scheduling.prisma`, `resource.prisma`. Module models live ONLY in these files (never `ops.prisma`, `platform.prisma`, `academic-quality.prisma`, `communication.prisma`): Committee/CommitteeReport -> `committee.prisma`; Portfolio..CQIItem -> `portfolio.prisma`; Meeting/AgendaItem/Decision/MeetingAttendance/Appointment -> `meeting.prisma`; GeneratedReport/ReportDefinition/ExportFormatSpec -> `reporting.prisma`; DashboardProjection -> `dashboard.prisma`; Announcement -> `notification.prisma`; AnnualPlan/QuarterlyReport -> `planning.prisma`; LoadCycle/ReviewedPreference/LoadExport -> `load.prisma`; ExamSchedule..DutyAssignment -> `scheduling.prisma`; Asset/MaintenanceRecord -> `resource.prisma`. Files for later milestones exist (empty comment) from Phase 1.
- **Ids are text (`cuid()`) everywhere**, never uuid, because better-auth ids are text and `Department.id === Organization.id`. RLS policies compare text to text with **no cast**. Departments are therefore never seeded with fixed ids: `prisma/seed/departments.ts` calls `departmentService.create()` (tenancyAndAuth §2), which creates the better-auth Organization first and copies its id.
- Shorthands used below:
  - `Id` = `id String @id @default(cuid())`; `Ts` = `createdAt DateTime @default(now())` + `updatedAt DateTime @updatedAt`; `RV` = `rowVersion Int @default(1)` (optimistic concurrency: services pass `where: { id, rowVersion }`).
  - `TENANT` = `departmentId String` + `department Department @relation(fields: [departmentId], references: [id], onDelete: Restrict)` + `@@index([departmentId])`; `TENANT?` = same with `String?` (NULL = faculty-wide shared row).
  - `REF(x)` = `xType SubjectType` + `xId String` + `@@index([xType, xId])` (no FK; `SubjectRegistry.exists` is enforced on write); `REF(x)?` = both nullable.
  - `FK Model` = `modelId String` + `model Model @relation(fields: [modelId], references: [id])`; `FK?` = nullable with `onDelete: SetNull`; `(Cascade)` = `onDelete: Cascade`. Self-relations and double FKs to one model carry an explicit `@relation("Name")`.
- Every model has `@@map("snake_case_table")` and every column `@map("snake_case")` (`prisma/scripts/check-schema.ts` fails if any field other than `id` lacks `@map`). **All hand-written SQL therefore uses snake_case identifiers** (`department_id`, `start_at`, `body_text`, `acl_tokens`, `owner_type`, `campaign_id`); `gen-rls.ts` reads `dbName` from the DMMF for tables and columns, never the Prisma field names.
- Enum values are lower_snake (`published`, `active`, `planned`); where featureBuilder §2 spells them `PUBLISHED`/`ACTIVE`/`PLANNED` read the lower_snake value (the TypeScript code uses the generated enum constants, so the spelling is decided here once).
- Json column names follow the owning design part (`data`, `json`, `compiledJson`, `stateMap`, `branchStates`, `settingsJson`); every Json column has a Zod schema registered in `src/lib/db/json-schemas.ts` (`"<Model>.<field>" -> ZodType`, checked by `check-schema.ts`).
- Child tables whose parent carries tenancy STILL carry `departmentId` (denormalised) unless listed under GLOBAL in §21.
- The `pgboss` schema is owned by `dept_app` and migrated by pg-boss itself; no Prisma model references it and Prisma migrations never touch it.

## 22. Hand-written migrations
Folder names are Prisma's timestamped `<yyyymmddhhmmss>_<name>`; the plan refers to them by name only. Each is created with `docker compose run --rm web npx prisma migrate dev --create-only --name <name>`, then SQL is appended, then `docker compose run --rm web npx prisma migrate dev`. Roles, databases and the `pgboss` schema are created ONLY by `docker/postgres/init.sql` (dockerDev): `dept_migrator` (LOGIN, CREATEDB, BYPASSRLS, owner of dept/dept_test/dept_e2e) and `dept_app` (LOGIN, NOBYPASSRLS), with `ALTER DEFAULT PRIVILEGES FOR ROLE dept_migrator` grants; migrations never `CREATE ROLE`/`CREATE SCHEMA` (cluster-wide statements would fail on the second database and in per-run test schemas).
1. `extensions` (P1, first migration): `CREATE EXTENSION IF NOT EXISTS pg_trgm; CREATE EXTENSION IF NOT EXISTS btree_gist;` (trusted extensions; idempotent because init.sql already created them in `dept`).
2. `init` (P1): Prisma-generated tables for the P1 models; later phases add `<name>` migrations per phase (`p3_people`, `p12_committee`, ...).
3. `rls` (P1) and `rls_<phase>` (every phase that adds a tenant model): GENERATED by `prisma/scripts/gen-rls.ts --append prisma/migrations/<stamp>_<name>/migration.sql`. Per strict table T (dbName): `ALTER TABLE "T" ENABLE ROW LEVEL SECURITY; ALTER TABLE "T" FORCE ROW LEVEL SECURITY; CREATE POLICY tenant_isolation ON "T" USING (department_id = current_setting('app.current_department_id', true) OR current_setting('app.tenant_bypass', true) = 'on') WITH CHECK (department_id = current_setting('app.current_department_id', true) OR current_setting('app.tenant_bypass', true) = 'on');`. Nullable variant: USING gets `department_id IS NULL OR ...`, WITH CHECK gets `(department_id IS NULL AND current_setting('app.tenant_bypass', true) = 'on') OR ...`. Header `-- generated by gen-rls.ts; manifest-hash=<sha256>`.
4. `search` (P11): `ALTER TABLE search_index_entry ADD COLUMN search tsvector GENERATED ALWAYS AS (setweight(to_tsvector('simple', coalesce(title,'')),'A') || setweight(to_tsvector('simple', coalesce(body_text,'')),'B')) STORED; CREATE INDEX search_index_entry_search_idx ON search_index_entry USING GIN (search); CREATE INDEX person_full_name_trgm ON person USING gin (full_name gin_trgm_ops); CREATE INDEX course_title_trgm ON course USING gin (title gin_trgm_ops); CREATE INDEX document_title_trgm ON document USING gin (title gin_trgm_ops); CREATE INDEX document_version_text_idx ON document_version USING GIN (to_tsvector('simple', coalesce(extracted_text,'')));`
5. `constraints` (P1 for the kernel tables; later phases append `constraints_<phase>` for their tables), all snake_case:
   - `ALTER TABLE availability_block ADD CONSTRAINT no_hard_overlap EXCLUDE USING gist (owner_type WITH =, owner_id WITH =, tstzrange(start_at, end_at) WITH &&) WHERE (severity = 'hard' AND weekday IS NULL); ALTER TABLE availability_block ADD CONSTRAINT block_range_valid CHECK (end_at > start_at);`
   - `CREATE UNIQUE INDEX section_rep_primary ON section_representative (section_id, academic_year_id) WHERE is_primary AND valid_to IS NULL; CREATE UNIQUE INDEX role_key_global ON role (key) WHERE department_id IS NULL; CREATE UNIQUE INDEX feature_definition_key_global ON feature_definition (key) WHERE department_id IS NULL;`

## 2. Organization = Department mapping
- One `Organization` per department; `Department.id === Organization.id` and `Department.organizationId` holds the same value (unique FK). `departmentService.create({ code, name })` (`src/platform/people/departments.ts`, admin-only or seed, inside `withTenantBypass`): `const org = await auth.api.createOrganization({ body: { name, slug: code.toLowerCase(), metadata: { code } }, headers })` (seed passes a server-side admin session created with `auth.api.signInEmail`), then `prismaRoot.department.create({ data: { id: org.id, organizationId: org.id, code, name } })`; if the second write fails the organization is deleted (compensation). `prisma/seed/departments.ts` uses this service, so seeded departments (CS, EE) get better-auth ids. `session.activeOrganizationId` therefore IS the `departmentId` used for RLS.
- `Organization.slug` = lower-case department code = the `[dept]` URL segment.
- `Member.role` = comma-separated `OrgRoleKey`s (`"instructor,committee_member"`); it is the source of department-wide roles and is materialised by `derive.ts` into `RoleGrant(scopeType=department, scopeId="", source=derived, derivedFromType=user, derivedFromId=userId)` rows so `can()` reads RoleGrant only.
- Relations: `User 1—0..1 Person` (`Person.userId @unique`); `Person 1—* DepartmentPerson` (tenant link); `StaffProfile`/`Student` keyed by `personId` per department (a person teaching in two departments has two StaffProfiles). `Member` rows exist only for persons with a User; `DepartmentPerson` exists for every person the department works with (students, externals, reps without accounts).
- Provisioning `identityService.provisionUser({ personId, departmentId, roleKeys })` (`src/platform/identity/provision.ts`; admin action or the representative auto-invite): (1) `auth.api.createUser({ body: { email, name, password: randomBytes(24).toString("base64url"), role: "user", data: { emailVerified: true } } })`; (2) `prismaRoot.person.update({ where: { id: personId }, data: { userId } })` + `DomainEvent person.user_linked`; (3) `auth.api.addMember({ body: { organizationId: departmentId, userId, role: roleKeys.join(",") } })`; (4) `auth.api.requestPasswordReset({ body: { email, redirectTo: "/set-password" } })` -> Mailpit in dev (`SMTP_URL=smtp://mailpit:1025`, e2e reads `MAILPIT_URL`); (5) `AuditEvent(permission_change)`. Idempotent: existing `Person.userId` skips 1–2; existing member -> `updateMemberRole` merges roles. Global System Administrator = `user.role === "admin"`; admins hold no Member rows unless they also work in a department.

export function forDepartment(departmentId: string) {

    name: `dept:${departmentId}`,
    query: { $allModels: { async $allOperations({ model, operation, args }) {

      });

```ts
export async function withTenantTx<T>(departmentId: string, fn: (tx: Prisma.TransactionClient) => Promise<T>, opts?: { maxWait?: number; timeout?: number }) {
  return prismaRoot.$transaction(async (tx) => { await tx.$executeRaw`SELECT set_config('app.current_department_id', ${departmentId}, true)`; return fn(tx); }, { maxWait: 5000, timeout: 15000, ...opts });
}
export async function withTenantBypass<T>(ctx: { isAdmin: true; user: { id: string } } | { worker: true; jobName: string }, reason: string, fn: (tx: Prisma.TransactionClient) => Promise<T>) {
  return prismaRoot.$transaction(async (tx) => {
    await tx.$executeRaw`SELECT set_config('app.tenant_bypass', 'on', true)`;
    await tx.auditEvent.create({ data: { action: "tenant_bypass", subjectType: "department", subjectId: "*", reason, actorUserId: "user" in ctx ? ctx.user.id : null } });
    return fn(tx);
  });
}
```

## 5. Permission checks: `can(actor, permissionKey, subjectRef?)` (`src/platform/identity/can.ts`)
Result `{ allowed: boolean; level: PermissionLevel; reason: string }`, memoised per request by `React.cache` on `(userId, departmentId, key, subjectType, subjectId)`.
- `actor: Actor = { userId, personId: string | null, departmentId, isAdmin, orgRoles, roleKeys }` (= `Ctx`).
- Key resolution `resolvePermissionKey(key, ctx)`: specific keys `'{prefix}.{action}'` (e.g. `evaluation.close` from a campaign preset `permissionPrefix`) fall back to the generic key (`campaign.manage`) when not registered in `Permission`; feature permissions are `feature.<featureKey>.<view|create|manage|act.<actionKey>>`, compiled into `Permission`/`RolePermission` rows at publish (featureBuilder §3 step 10), so built-in and admin-defined features use the same function.
- Evaluation order (first decisive step wins):
  1. `isAdmin` -> `{ allowed: true, level: 'full' }` (except keys flagged `adminExcluded` such as `submission.respond`).
  2. Explicit deny: any effective `RolePermission.level = 'none'` for one of the actor's active grants on that key -> denied.
  3. Effective RolePermission rows = department override rows (`departmentId = actor.departmentId`) ∪ faculty rows (`departmentId IS NULL`) not overridden, for roles the actor holds through active `RoleGrant` rows (`validFrom <= now < validTo | null`) in this department. Department-scope grants with `full` -> allow; `manage` -> allow unless key ∈ `SystemSetting('rbac.manageExcludedPermissions', department)` (defaults `portfolio.approve, evaluation.close, evaluation.analyze, plan.approve, minutes.approve`).
  4. Scoped grants (`scopeType ∈ committee | section | program | section_offering | lab_schedule | meeting | feature_record`) apply only when `subjectRef` is given and `SubjectRegistry.contextOf(subjectRef)` contains `(scopeType, scopeId)` (a task with `contextRef = committee:C1` is inside `committee@C1`; a feature record with `parentSubject` inherits the parent's context when `inheritPermissions`). Level from that role's RolePermission.
  5. Level semantics, with `rels = SubjectRegistry.relationships(subjectRef, actor.personId)`: `full`/`manage` as above; `review` = read plus transitions whose actor rule is `reviewer` when `rels` includes `reviewer` or the actor holds `review` at department scope; `own` = `rels` includes `owner`; `assigned` = `rels` includes `assignee` (direct, via group, via adhoc audience group, or an ACTIVE `FeatureStepInstance` assigned to the actor) or `member`/`chair` of the context group; `participate` = `rels` includes `target` or `participant` (campaign invitation holder, meeting participant); `limited` = read + comment only when `rels` includes `requester`, or `participant` of a meeting whose minutes are approved, or the actor is a current `SectionRepresentative` of `contextOf(subject).sectionId`; `view` = read only; `submit` = create + edit own Submissions only. Action verbs map to level requirements in `src/platform/identity/levels.ts` (`read` by any level except `none`; `comment` by limited+; `act` by assigned/own/participate+; `manage` by manage/full).
  6. Nothing matched -> `{ allowed: false, level: 'none', reason }`; `requireCan()` throws `ForbiddenError` and writes `AuditEvent(action = denied)`.
- Workflow transitions: `Workflow.apply` calls `can(actor, transition.requiredPermission ?? resolvePermissionKey(...), subjectRef)` and then evaluates `transition.actorRules` (featureBuilder `ActorRule`: owner/creator/assignee/role/relationship/permission/person/group/record_field/system) with the same `relationships()` result; a transition is allowed iff both hold.
- Every server action and route handler starts `const ctx = await requireDeptContext(input.dept); const db = await getDb(); await requireCan(ctx, 'task.manage', ref);` (wrapped by `safeAction`). Tests: `tests/unit/identity/can.test.ts` (one fixture per level and per evaluation step, in-memory grants, stubbed SubjectRegistry), `tests/unit/identity/matrix.test.ts` (seeded §30 matrix: DH full / DPT manage minus exclusions / instructor own+assigned / committee_member assigned / committee_chair assigned + `committee.task.manage`, `committee.report.submit` / student_rep limited+participate / student submit / lab_staff assigned@lab_schedule), `tests/integration/identity/can-db.test.ts` (real RolePermission overrides, derived grants).

## 6. Derived RoleGrant sync (`src/platform/identity/derive.ts`) and nightly reconcile (`reconcile.ts`)
- Outbox subscribers registered in `src/platform/audit/subscribers.ts`, each idempotent through `EventHandlerReceipt(eventId, handlerKey)`:
  - `member.changed` -> for each role in `Member.role`: upsert `RoleGrant(userId, roleId(key), scopeType=department, scopeId="", source=derived, derivedFromType=user, derivedFromId=userId)`; expire (`validTo = now`) department grants for roles no longer listed. `member.removed` -> expire all derived department grants of that user in that department.
  - `group.membership.changed` (GroupMembership insert/update/delete on `Group.kind = committee`) -> `committee_member@committee:<Committee.id>` (+ `committee_chair` when `roleInGroup = chair`), `derivedFromType = group_membership`, `derivedFromId = <membership id>`; `validFrom/validTo` copied from the membership.
  - `group.status.changed` (inactive) -> `validTo = now` on grants derived from memberships of that group; (active) -> restore rows whose membership is still open.
  - `teaching.assigned` / `teaching.ended` -> `instructor@section_offering`, `derivedFrom = teaching_assignment:<id>`.
  - `representative.changed` -> `student_rep@section`, `derivedFrom = section_representative:<id>`; if `Person.userId` is null -> `identityService.provisionUser({ personId, departmentId, roleKeys: ['student_rep'] })` (§2); the grant is written when `person.user_linked` arrives (the handler returns without a receipt error and re-runs on that event).
  - `student.section_membership.changed` -> `student@section` for students with a User; persons without a User get no grant (they act through tokens, §7).
  - `duty.assigned` (lab) / `duty.ended` -> `lab_staff@lab_schedule`.
  - `person.user_linked` -> runs `reconcilePerson(personId)` immediately (all expected derived grants for that person across departments).
- Nightly `grant.reconcile` (pg-boss cron `0 3 * * *`, tz `APP_TIMEZONE`, queue policy `standard`, handler `apps/worker/src/handlers/reconcile.ts`, runs under `withTenantBypass({ worker: true, jobName: 'grant.reconcile' }, 'nightly reconcile')`): per department computes the expected derived set from Member, open GroupMembership(committee), open TeachingAssignment, open SectionRepresentative, open StudentSectionMembership, open lab DutyAssignment; diffs against `RoleGrant WHERE source = 'derived'`; inserts missing, expires extra (never deletes); writes one `AuditEvent(permission_change, reason = 'grant_reconcile', fieldChangesJson = { added, expired })` per department and a `ScheduledJob` ledger row. `tests/integration/identity/grant-reconcile.test.ts`: corrupt a grant, run the handler, assert repair, assert a second run changes nothing.
- Manual grants (`source = manual`, e.g. an `appointment.manage` delegate or a `committee_chair` override) are never touched by reconcile; `/d/[dept]/admin/grants` edits them with audit.

## 7. Persons without a User (token links)
- `notify()` for a `recipientPersonId` whose Person has no `userId` creates no `in_app` delivery, only `email` (later `sms`); the template's `{{action_url}}` becomes a token link.
- Campaign links `/c/[token]` (`src/app/c/[token]/page.tsx`): token = 32 random bytes base64url, stored only as `CampaignInvitation.tokenHash = sha256(token)`; `openLink(token)` finds the hash, checks `status != expired` and `expiresAt`, renders the pinned FormDefinition without a session; submit writes `Submission` per anonymity mode (anonymous: `respondentPersonId` and `invitationId` NULL, invitation marked `submitted` in a second statement); rate-limited per IP; single-use unless `submissionRule = editable_until_close` (token valid until `resolvedClosesAt`).
- Appointment public form `/a/[hostSlug]` (`SystemSetting('appointments.publicRequests')`): the `appointment.publicIntake` backing adapter creates `Person(type = external)` + `DepartmentPerson`, the `appointment_request` Submission and the `appointment` FeatureRecord (+ `Appointment` row); the confirmation e-mail carries `/a/[hostSlug]/[token]` where token is a `jose` HS256 JWT signed with `BETTER_AUTH_SECRET` (`{ sub: featureRecordId, dept, exp }`) that opens a read-only status page with cancel / accept-reschedule actions. `verifyPublicLink(token) -> { featureRecordId, departmentId }` then `withTenantTx(departmentId, ...)`.
- Representative auto-invite (§6) is the only path that turns a person without a login into a user automatically; other students stay token-only (open question recorded in the plan).
- All public routes run under `withTenantTx(departmentId from the invitation/token)`, never `getDb()`, and log `AuditEvent(actorUserId = null, action = create | update, subjectRef)`. `tests/e2e/public-links.spec.ts` covers an anonymous evaluation via a Mailpit link and an external appointment request without login.
